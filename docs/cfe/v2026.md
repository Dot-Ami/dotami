# CFE v2026 Catalog

The Canadian Financial Engine (CFE) is DotAmi's lifecycle catalog. The cockpit's tier columns are the showroom; the CFE catalog is the factory.

This document defines the authoring rules for `lib/engines/cfe/v2026/`.

Current status: the CFE v2026 catalog holds the lifecycle nodes the map draws (`nodes.ts`) and the tier columns that group them (`tiers.ts`). Every node carries citations; `tests/engine-integrity.spec.ts` refuses one without.

## Directory Contract

```text
lib/engines/cfe/
  index.ts
  v2026/
    index.ts
    nodes.ts
    tiers.ts
    types.ts
```

Catalog data is code, not database content. Keep CFE nodes in TypeScript files so regulatory updates are reviewable in git and future year versions can be drop-in replacements.

## Node Interface

Every node must satisfy `CFENode` from `lib/engines/cfe/v2026/types.ts`.

Required fields:

- `id`
- `label`
- `stage`
- `trigger`
- `description`
- `taxImpact`
- `lensAnnotations.tax`
- `lensAnnotations.legal`
- `citations`
- `financialImpact`
- `branches`

## Citation Rules

Every node needs at least one CRA or provincial citation. Use official sources first:

- CRA for GST/HST, payroll, sole proprietorship, corporation, SBD, SR&ED, records.
- Provincial sources for business registration and employment standards.
- Federal sources such as Corporations Canada when CRA is not the legal authority.

Every citation must include:

- `title`
- `authority`
- `jurisdiction`
- `url`
- `lastVerified`
- `note`

Use ISO date strings for `lastVerified`.

## Compliance Language

CFE copy must be conditional and explanatory.

Avoid:

- "you should"
- "you need to"
- "the right choice is"

Prefer:

- "if X, this unlocks Y"
- "when X happens, this becomes a compliance gate"
- "model A against B"

The CFE should surface options and consequences, not advice.

## Branching Rules

Branches are node IDs, not labels. Branches must point to existing node IDs unless the branch intentionally targets a future catalog node in a later version.

For v0, keep branching depth small:

- GST timing branch: voluntary vs mandatory registration.
- Incorporation timing branch: income-triggered vs liability/SR&ED-triggered incorporation.

## Financial Impact Rules

`financialImpact` should explain how the node changes projection behavior. It does not need to be a full calculator.

Include:

- `summary`
- `projectionNotes`
- `estimates`

Estimates may include statutory values, PRD heuristics, or modeling labels. If a value is a heuristic rather than law, say so in `basis`.

## Versioning Rules

Do not mutate older year catalogs after a new year version exists except to fix typos or broken links.

When regulatory rules change:

1. Create a new year directory, for example `lib/cfe/v2027/`.
2. Copy the previous version.
3. Update affected nodes and citations.
4. Update the root CFE export only after tests pass.
5. Add or update golden scenario fixtures for changed behavior.

## Verification

Run these checks after CFE changes:

- TypeScript compile for `lib/cfe/index.ts`.
- Lint diagnostics for `lib/cfe`.
- Search for prohibited prescriptive language such as `you should`.
- Confirm node count and citation coverage.
- Run `npm run test` (Vitest) for golden scenario regression; fixtures in `tests/fixtures/golden-scenarios.ts`.

Golden scenarios must match published structural recommendations exactly and numbers within +/-10%.
